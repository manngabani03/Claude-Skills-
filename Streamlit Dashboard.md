# Streamlit Dashboard Skill

Generates a complete, runnable Streamlit dashboard Python app from structured data.
No placeholders — every chart, filter, tab, and download button is fully implemented.

---

## Step 1 — User Intake

Ask all questions in one message before writing any code:

> 1. **What is the name of this dashboard?** (used as the page title and filename)
> 2. **What data are we dashboarding?** Paste the column names and types, or confirm it
>    came from the file-parser or data-analyst skill.
> 3. **What date range should the dashboard default to on load?** (e.g. "last 30 days",
>    "all data", "Jan 2024 – Dec 2024")
> 4. **Which sheets or data sections should each become a separate tab?**
>    (e.g. "Sales, Inventory, Summary" → 3 tabs)
> 5. **Do you want a raw data table with a Download CSV button on every tab?**
>    (default: yes)
> 6. **What color theme do you prefer?** light / dark / default
> 7. **Data storage format:** should the app read from a **CSV file** or a **SQLite
>    database**? (CSV = simpler; SQLite = faster for large data)

Wait for the user's response. Use their answers to fill every variable in the generated code.

## Step 2 — Analyse the Data Schema

Before generating code, reason through the schema the user provided:

- **Date column**: identify the column that holds timestamps/dates → used for date picker
- **Categorical columns**: string columns with < 50 unique values → used for sidebar filters
- **Numeric columns**: float/int columns → used for KPI cards and charts
- **High-cardinality columns**: strings with many unique values (IDs, names) → display-only,
  don't use as filters
- **Auto-select chart types per tab**:
  - If date col + numeric col → Line chart (trend over time)
  - If categorical col + numeric col → Bar chart (comparison)
  - If 2 numeric cols → Scatter plot (correlation)
  - If single numeric col → Histogram (distribution)

Document this reasoning briefly in a comment block at the top of the generated file.

## Code Quality Rules

Always follow these in every generated file:

1. **No placeholders** — every function, filter, chart, and button is real working code
2. **`st.cache_data`** on all data loading functions — never re-read on every rerender
3. **Comments on every section** — `# ── Section Name ───` dividers throughout
4. **Error handling** — always check `if df.empty` after filtering; always use `errors="coerce"` on date parsing
5. **Cross-platform paths** — always use `Path(__file__).parent / "filename"` never hardcoded string paths
6. **Download buttons** — every tab has one; use `io.StringIO` buffer pattern
7. **No global state mutation** — always `df = df_full[mask].copy()`, never modify `df_full`
8. **Column safety** — if a column might not exist, check with `if "col" in df.columns`

## Edge Cases

| Situation | Action |
|---|---|
| No date column in data | Skip date picker; filter by row index range instead. Note in code. |
| Only one tab requested | Skip `st.tabs`; use sections with `st.header` instead |
| No categorical columns | Skip sidebar category filters; only show date picker |
| SQLite preferred | Generate `load_data_sqlite()` and instruct user to name table "data" |
| > 10 numeric columns | Auto-select top 4 most-variant columns for KPIs; offer all in a multiselect |
| User didn't specify default date range | Default to last 90 days or all data if < 90 days exist |
